Product Requirements Document (PRD): JCT MixExam1. Project OverviewApp Name: JCT MixExam (Placeholder)Goal: A fully offline, cross-platform mobile application (iOS & Android) that allows students to import PDF files of "Zero-Exams" (מבחני אפס - where the first answer choice is always the correct one). The app parses the PDF, extracts questions and answers, and creates an interactive practice environment. It shuffles the text answers to prevent memorization by position and provides immediate feedback on the correct answer.Core Principle: 100% offline processing to ensure privacy and local availability. Absolute preservation of data integrity (handling complex visual questions without breaking them).2. Technical Stack & InfrastructureFramework: Flutter (Dart) - Cross-platform mobile development.State Management: flutter_riverpod (Strict requirement for predictable state handling).Local Storage: sqflite or hive (To save parsed exams so heavy PDFs are processed only once). SharedPreferences for user settings (Theme).PDF Processing: syncfusion_flutter_pdf (or pdfx / native_pdf_renderer for visual bounding box extraction).UI/UX: Material 3 Design, full RTL (Right-to-Left) support, responsive Dark/Light mode depending on system settings or in-app toggle.3. Data Architecture (Models)AI Agents must implement the following Dart models:class Exam {
  final String id;
  final String title;
  final List<Question> questions;
}

class Question {
  final String id;
  final String questionText;
  final List<Answer> textAnswers; // Populated if isShufflable == true
  final bool isShufflable; // true if pure text, false if contains visuals
  final String? croppedImageUrl; // Question body only (without answers)
  final String? fullImageUrl; // Full original question with answers
}

class Answer {
  final String id;
  final String text;
  final bool isOriginalCorrect; // Always true for the FIRST extracted answer
}
4. PDF Parsing Engine (Core Logic)CRITICAL: PDF parsing is CPU and Memory intensive. All parsing logic MUST be executed in a separate background Isolate using Dart's compute() function to prevent UI thread freezing and OOM (Out Of Memory) crashes.Step-by-Step Parsing Flow:File Selection: Use file_picker to select a local PDF.Question Identification: Scan the document for the regex pattern matching "שאלה מספר X:" (Question number X:) or ".X " at the start of a line. This marks the start of a question block.Visual vs. Text Detection (Data Integrity):Evaluate the bounding box of the identified question block.If the block contains non-text elements (Images, Graphs, Vector drawings like Karnaugh maps or CPU diagrams), route to Path B.If the block is pure text, route to Path A.Path A: Pure Text Extraction (isShufflable = true)Extract the question text.RTL Fix (Bidi): PDF text extraction for Hebrew often reverses the characters. Apply a Bidi algorithm to reverse the characters in each line while preserving the order of numbers and English words.Answer Extraction: Detect lines starting with Hebrew bullet points "א.", "ב.", "ג.", "ד." (Aleph, Bet, Gimel, Dalet).Strip these leading bullet points from the extracted string.Flag the first extracted answer as isOriginalCorrect = true.Shuffle the answers array before presenting it to the UI.Path B: Visual Fallback & Smart Cropping (isShufflable = false)Convert the relevant PDF page section into an image.Smart Cropping: Locate the Y-coordinate where the answers begin (e.g., detecting the "א." bullet point). Crop the image vertically to keep only the question body and diagram, cutting out the original answers. Save this as croppedImageUrl.Save the uncropped image (with the Zero-Exam answers) as fullImageUrl.5. User Interface (UI/UX) FlowEnsure global Directionality is set to TextDirection.rtl.Screen 1: Home ScreenApp Bar: Title "My Practice Exams" (התרגולים שלי), Day/Night mode toggle button.Body: A ListView of previously imported and processed exams fetched from local DB.Action: A prominent Floating Action Button (FAB) with a + icon to import a new PDF.Screen 2: Loading & ProcessingDisplays a CircularProgressIndicator while the Isolate parses the PDF.Upon completion, displays a summary: "Exam extracted successfully. X questions found."Button: "Start Practice" (התחל תרגול).Screen 3: Active Practice ScreenQuestions are presented using a Swipeable Card interface or a vertical scrolling list.Dynamic UI based on Question Type:Text Questions (isShufflable == true):Display question text.Display shuffled answers as selectable interactive cards/radio buttons.Helper Feature: An "Eye" icon button underneath the question labeled "Reveal Correct Answer". Tapping it highlights the answer with isOriginalCorrect == true in bright green, allowing immediate self-checking without failing the user.Visual Questions (isShufflable == false):SILENT UX RULE: Do NOT show any label, warning, or popup indicating that this question is not shuffled. The transition must be seamless.Display the croppedImageUrl (Question body and diagram only).Instead of interactive radio buttons, display a single prominent button: "Reveal Original Answers" (הצג פתרון מקורי).Tapping this button replaces the cropped image with fullImageUrl (showing the original Zero-Exam layout where the first answer is correct) so the user can verify their manual calculation.Footer: "Finish Practice & Show Score" button.Screen 4: Results ScreenDisplays the final score as a percentage (e.g., 85%).Displays a list of only the incorrect answers.For each mistake, show the selected answer in Red and the correct answer in Green.6. Strict Directives for AI Code AgentsArchitecture: Strictly follow Clean Architecture principles. Separate UI, State (Riverpod), and Parsing Logic (Repositories/Services).No External APIs: The app must be 100% offline. Do not use HTTP requests to send PDFs to external servers. Use local Dart packages only.Thread Safety: You MUST use compute() for all PDF loading, regex scanning, Bidi reversing, and image cropping. Main thread blocking is unacceptable.Bidi Reversal: You must account for RTL character reversal from standard PDF text extraction. Write or implement a robust Bidi fix for the Hebrew text.Smart Cropping Enforcement: Never show the fullImageUrl by default for Visual Questions, as it exposes the Zero-Exam structure immediately and ruins the practice. Always default to croppedImageUrl until user interaction.
